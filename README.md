## 01 · 🧠 NORA

### Agency Operations, Knowledge Graph & AI Agent Platform

<sub>Python · FastAPI · PostgreSQL · pgvector · LangGraph · SvelteKit</sub>

<div align="center">

<img src="https://img.shields.io/badge/303-Reported%20Passing%20Tests-16A34A?style=for-the-badge&logo=pytest&logoColor=white" alt="303 reported passing tests"/>
<img src="https://img.shields.io/badge/RAG-PGVector-7C3AED?style=for-the-badge" alt="RAG and pgvector"/>
<img src="https://img.shields.io/badge/Architecture-Layered-0891B2?style=for-the-badge" alt="Layered architecture"/>

</div>

NORA is a full-stack agency operations platform connecting client, lead, project, and task workflows with AI-powered knowledge retrieval and tool execution.

**Backend architecture**

- Designed relational entities for Clients → Leads → Projects → Tasks using PostgreSQL, foreign keys, cascading deletion, and REST APIs.
- Implemented a layered **Router → Service → Repository** backend using SQLAlchemy 2.x, Pydantic, Pydantic Settings, and Alembic migrations.
- Expanded the Pytest / HTTPX integration suite from 134 to **303 reported passing tests**, covering APIs, schema validation, session persistence, retrieval, tools, confirmations, and workflow scenarios.

**Knowledge intelligence — RAG + pgvector**

- Implemented semantic retrieval using PostgreSQL pgvector.
- Designed entity-aware knowledge indexing for Clients, Leads, Projects, and Tasks.
- Added idempotent re-indexing, similarity scoring, and an EmbeddingProvider abstraction.
- Built the RAG flow: retrieval → entity-aware context → structured LLM generation → grounded answer with source metadata.
- Included no-context fallback and provider error handling.

**LangGraph and conversational memory**

- Implemented a typed `OrbitState` StateGraph with three branches:
  - 📚 Knowledge / RAG
  - 🛠️ Action / Tool
  - 💬 General LLM
- Added Client, Lead, Project, and Task tools.
- Implemented confirmation-gated mutations using an `action_id` confirmation workflow.
- Built bounded multi-turn memory, PostgreSQL-backed session persistence, and entity-aware follow-up resolution such as ordinal and contextual references.

**Core stack**

`FastAPI` `PostgreSQL` `pgvector` `SQLAlchemy` `Alembic` `LangGraph` `OpenAI` `SvelteKit` `Svelte 5` `TypeScript` `Pytest` `HTTPX`

## 04 · 🔄 WhatsApp Lead Engagement & CRM Data Pipeline

### Event-Driven ETL + AI Classification

<sub>n8n · Supabase · PostgreSQL · WhatsApp API · Google Gemini · React</sub>

<div align="center">

<img src="https://img.shields.io/badge/ETL-Data%20Pipelines-0891B2?style=for-the-badge" alt="ETL pipelines"/>

Designed an event-driven pipeline for capturing, normalising, classifying, and tracking leads from WhatsApp-driven workflows.

**Pipeline design**

1. 📥 **Ingest:** capture incoming leads through webhook events.
2. 🧹 **Transform:** normalise fields and validate structured payloads.
3. 🗄️ **Store:** persist records in PostgreSQL through Supabase.
4. 🧠 **Classify:** use Google Gemini for AI-assisted lead classification.
5. 📈 **Score:** calculate lead scores and update CRM records.
6. 🔔 **Automate:** trigger CRM updates and event-driven alerts.
7. 📊 **Monitor:** surface pipeline activity through a React dashboard.

**Engineering focus**

- Structured ingestion and schema validation.
- Reliable webhook-to-database processing.
- AI-integrated data transformation.
- CRM workflow automation and pipeline visibility.

`ETL / ELT` `Webhooks` `PostgreSQL` `Gemini` `n8n` `React`
