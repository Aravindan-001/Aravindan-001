### 01 — NORA | AI Agency Operations & Knowledge Platform

<a href="https://github.com/Aravindan-001">
<img align="right" width="110" src="https://img.shields.io/badge/AI-PLATFORM-0891B2?style=for-the-badge&logo=probot&logoColor=white" alt="AI platform"/>
</a>

**A backend-first platform combining agency operations, knowledge retrieval, conversational context, and controlled AI actions.**

**Core engineering**
- FastAPI backend with SQLAlchemy 2.x, Pydantic, and Alembic.
- PostgreSQL with pgvector for entity-aware knowledge retrieval.
- LangGraph workflow routing across **Knowledge, Action, and General** branches.
- Persistent conversational context and entity-aware follow-up resolution.
- Retrieval → context assembly → structured generation → grounded response with source metadata.
- Action tools for operational CRUD workflows, with confirmation-gated mutations using `action_id`.
- SvelteKit and Svelte 5 frontend with an ORBIT conversational interface.

**Architecture**

```mermaid
flowchart TD
    U[User / SvelteKit UI] --> API[FastAPI]
    API --> R[LangGraph Router]
    R --> K[Knowledge Branch]
    R --> A[Action Branch]
    R --> G[General Branch]
    K --> V[PostgreSQL + pgvector]
    K --> L[Context + Grounded Generation]
    A --> T[Operational Tools]
    T --> C[Confirmation Gate]
    C --> DB[Clients / Leads / Projects / Tasks]
    G --> LL[LLM Response]
    L --> O[Response + Source Metadata]
    LL --> O
    DB --> O
```

**Engineering emphasis:** separation of concerns, retrieval quality, persisted context, safe mutation flows, database migrations, and automated testing.

**Test suite:** 303 tests reported for the project.

**Stack:** `Python` `FastAPI` `PostgreSQL` `pgvector` `LangGraph` `SQLAlchemy` `Alembic` `SvelteKit` `Pytest` `HTTPX`

## `05 / HOW I ENGINEER`

</div>

| Engineering layer | My approach |
|---|---|
| Architecture | Separate routing, business logic, data access, and external integrations |
| Data | Model entities carefully, manage schema changes, validate inputs, and preserve data integrity |
| AI workflows | Route intents, retrieve relevant context, constrain tools, and return grounded responses |
| Security | Apply authentication, authorization, server-side validation, and controlled state transitions |
| Reliability | Test critical paths, handle errors explicitly, and make asynchronous workflows observable |
| Delivery | Use version control, environment-specific configuration, reproducible builds, and deployment checks |

### Typical backend architecture

```text
┌──────────────────────────────────────┐
│           Client / Frontend          │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│       API Routes / Controllers       │
│       Validation · Authentication    │
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│           Service Layer              │
│       Business Rules · Workflows     │
└──────────────┬───────────┬───────────┘
               ▼           ▼
┌────────────────────┐  ┌───────────────────┐
│ Repository / ORM   │  │ External Services │
└──────────┬─────────┘  └───────────────────┘
           ▼
┌──────────────────────────────────────┐
```
